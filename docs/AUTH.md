# 인증 설정 및 운영 전 확인

Better Auth는 PostgreSQL에 사용자·세션·자격 증명을 저장합니다. 회원가입 후 메일의 확인 링크를 열고 로그인한 다음 초대 코드를 입력해야 학생 권한이 활성화됩니다. 관리자 권한은 회원가입 입력으로 지정할 수 없습니다. 첫 관리자의 권한은 이메일 소유 확인을 마친 계정에 대해 신뢰할 수 있는 운영자가 데이터베이스에서 별도로 부여해야 합니다. 고정 관리자 계정이나 기본 비밀번호는 제공하지 않습니다.

`.env.example`에 따라 `DATABASE_URL`, 고유한 32바이트 이상의 `BETTER_AUTH_SECRET`, `INVITATION_SECRET`, 실제 사이트 URL `BETTER_AUTH_URL`과 SMTP 설정을 지정하고 마이그레이션을 적용하세요. SMTP는 포트 465에서 TLS, 다른 포트에서 STARTTLS를 요구합니다. 인증 메일 발송은 실제 SMTP 서버와 자격 증명이 있어야 하며, 이 저장소에는 SMTP 서비스나 자격 증명이 제공되지 않습니다. 메일 전송과 확인 링크는 실제 환경에서 반드시 검증해야 합니다. 비밀번호 재설정 메일 발송 및 재설정 화면은 아직 구현하지 않았습니다.

초대 코드 발급 시 원문은 한 번만 반환하며 저장하지 않습니다. `POST /api/admin/invitations/[id]/revoke`는 미사용 코드를 폐기합니다. 인증 요청과 초대 코드 시도 제한은 PostgreSQL에 저장되어 재시작과 여러 인스턴스에서 유지됩니다. 초대 코드는 계정별 15분에 5회까지 시도할 수 있습니다. Better Auth가 신뢰할 수 있는 클라이언트 IP를 확인하지 못하면 같은 경로의 요청은 공유 제한에 묶이므로, 운영 환경의 프록시 신뢰 경계와 외부 요청 제한을 설정하고 검증해야 합니다. HTTPS와 시크릿 관리, SMTP 발송, 관리자 계정 부여 및 재설정 흐름을 실제 운영 전에 확인해야 합니다.
